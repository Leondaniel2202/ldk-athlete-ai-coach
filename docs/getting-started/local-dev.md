# Local Development

This guide describes the expected local workflow for working on the backend and the
frontend.

The repository uses a monorepo structure with separate `backend/` and `frontend/`
directories. The root `Makefile` is the canonical developer entry point for both.

## Prerequisites

- Python `3.12`
- `uv`
- Node.js `20` or later (for the frontend)
- Docker Desktop or another Docker runtime that supports `docker compose`
- A Notion integration token and the required data source IDs if you need to run sync
- An OpenAI API key if you need to use the AI analysis endpoints

## Environment Setup

Create a local backend `.env` file from the checked-in template:

```powershell
Copy-Item backend/.env.example backend/.env
```

At minimum, the application requires:

- `POSTGRES_DB`
- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `POSTGRES_HOST`
- `POSTGRES_PORT`
- `NOTION_API_KEY`
- `NOTION_PLAN_DATA_SOURCE_ID`
- `NOTION_PHASE_DATA_SOURCE_ID`
- `NOTION_NUTRITION_GUIDELINE_DATA_SOURCE_ID`
- `NOTION_WORKOUT_DATA_SOURCE_ID`
- `NOTION_EVENT_DATA_SOURCE_ID`
- `NOTION_SESSION_DATA_SOURCE_ID`
- `NOTION_FEEDBACK_DATA_SOURCE_ID`

Optional but relevant:

- `OPENAI_API_KEY`
- `OPENAI_MODEL` is currently configured through settings and defaults to `gpt-4.1-mini`
- `TEST_POSTGRES_DB`, `TEST_POSTGRES_USER`, `TEST_POSTGRES_PASSWORD`, and
  `TEST_POSTGRES_PORT` can override the dedicated test database container values

The settings layer also accepts the legacy `*_DB_ID` Notion environment variables to
keep older local setups working during the migration to the newer Notion data source
API.

## Install Dependencies

### Backend

Preferred path:

```powershell
make backend-install
```

Direct `uv` equivalent:

```powershell
cd backend && uv --cache-dir ../.uv-cache sync --group dev
```

### Frontend

```powershell
make frontend-install
```

## Start the Databases

Start the development database:

```powershell
make backend-db-up
```

Start the dedicated test database:

```powershell
make backend-db-test-up
```

Stop all compose services:

```powershell
make backend-db-down
```

Docker Compose provides:

- `postgres` on `${POSTGRES_PORT:-5432}`
- `postgres_test` on `${TEST_POSTGRES_PORT:-5433}`

## Apply Migrations

Apply all current migrations:

```powershell
make backend-alembic-up
```

Create a new autogenerated migration:

```powershell
make backend-alembic-revision MSG="describe_change"
```

Alembic uses `backend/alembic.ini` and resolves imports via `prepend_sys_path = ./src`.

## Run the API

Start the FastAPI development server with reload:

```powershell
make backend-api
```

The Make target runs:

```powershell
cd backend && uv --cache-dir ../.uv-cache run uvicorn ldk_athlete_ai_coach.main:app --reload
```

Useful endpoints after startup:

- `GET /`
- `GET /api/v1/system/health`
- `GET /docs`

## Seed or Refresh Data

To populate the local database from Notion, call the sync endpoint after the API is
running:

```text
POST /api/v1/sync/notion
```

Optional query parameter:

- `hard_fail=false` by default
- `hard_fail=true` aborts the full sync on the first extraction or persistence error

Resource, context, and AI routes are only useful once the local database contains data.

## Common Backend Development Loop

1. `make backend-install`
2. `make backend-db-up`
3. `make backend-alembic-up`
4. `make backend-api`
5. Sync data from Notion if you need a fresh local dataset
6. Run focused tests while making changes
7. Run `make backend-lint`, `make backend-format-check`, and `make backend-type-check` before finishing

## Frontend Setup

The frontend lives in the `frontend/` directory and is a Next.js + React + TypeScript
application.

### Install frontend dependencies

```powershell
make frontend-install
```

Or directly with npm:

```powershell
cd frontend && npm install
```

### Configure the frontend environment

Copy the frontend environment template:

```powershell
Copy-Item frontend/.env.local.example frontend/.env.local
```

The only required variable for local development is:

- `NEXT_PUBLIC_API_BASE_URL` — defaults to `http://localhost:8000`, which is where the
  FastAPI backend runs.

### Run the frontend

```powershell
make frontend-dev
```

The development server starts at `http://localhost:3000`.

The frontend root redirects to the dashboard app shell. Start the backend first
(`make backend-api`) to see a connected backend status in the shell.

### Run the backend and frontend together

In two separate terminals:

**Terminal 1 — backend:**

```powershell
make backend-api
```

**Terminal 2 — frontend:**

```powershell
make frontend-dev
```

Visit `http://localhost:3000` to confirm the frontend redirects to `/dashboard`, the
main navigation renders, and the backend status badge shows **Backend connected**.

### Frontend quality checks

Lint:

```powershell
make frontend-lint
```

Check formatting:

```powershell
make frontend-format-check
```

Type check:

```powershell
make frontend-type-check
```

Build for production (optional, to verify the build passes):

```powershell
make frontend-build
```

## Troubleshooting

### The API cannot connect to Postgres

- Check that the compose service is running
- Verify `backend/.env` connection values
- Confirm migrations have been applied

### Notion sync fails immediately

- Confirm `NOTION_API_KEY` is valid
- Confirm each `NOTION_*_DATA_SOURCE_ID` matches the intended source
- If the API reports `502`, the downstream Notion call failed or access was denied
- If the API reports `503`, rate-limit retries were exhausted

### AI endpoints return `503`

- `OPENAI_API_KEY` is missing or invalid
- the OpenAI SDK request failed
- the provider returned no structured output or invalid structured output

### Windows virtual environment points to the wrong Python

If `.venv` references a missing interpreter, recreate the environment with Python `3.12`
and rerun `make backend-install`.
